# 顶栏数字模板匹配（stage / round_time）

> 代码：`utils/digit_tpl.py`　字模：`recognize/templates/stage_digits.npz`　接线：`recognize/extract.py::_extract_narrow`

## 一、为什么要有它

`stage`（回合号 `3-6`）和 `round_time`（倒计时 `20`）是**每个动作前都要读一次**的两个字段。
改造前这两项走顶栏横带 OCR：本机实测 **146ms（热）/ 590ms（含引擎启动）**，而它们只是两个阿拉伯数字。

改成 0~9 字模匹配后同一帧 **3.84ms**，加速 **38 倍**，结果完全一致（`3-6` / `20`）。

父项目（原 `jcc_robot`）的口径是 OCR 235~295ms → 4.74ms（约 50~60 倍），准确率 99.49%。
本脚手架用 GPU 跑 OCR，所以绝对耗时更低，但倍数同级。

## 二、怎么读的

四个步骤，全部是纯图像运算，不依赖 OCR：

1. **定区域**。`STAGE_LATE`（`2-x` 及以上）与 `STAGE_EARLY`（`1-x`，顶栏整体左移）两套坐标，
   `round_time` 也跟着选 `RT_LATE` / `RT_EARLY`——`read_stage` 读出 `stage` 后把命中的
   `"late"` / `"early"` 交给 `read_round_time`，后者不再自己猜位置。
2. **切数字**（`digit_boxes`）。固定高阈值 `max(150, max*0.70)` 二值化，再取外轮廓。
   两个实机坑写死在函数里：
   - **不能用 Otsu**：背景均值 77、白字 242，Otsu 会把整块连成 1 个连通域；
   - **`min_h=15` 过滤**：连字符 `-` 高 1~3px、装饰碎片高 10~12px，真数字高 17px。
3. **比字模**。每个连通域 `INTER_AREA` 缩放到 `TPL_SIZE=(20,28)`，与 npz 里每张字模做
   `TM_CCOEFF_NORMED`，取最高分的标签。字模当前 60 张（0~9 各 6 张，覆盖不同字体粗细/描边）。
4. **守合法性**。任一步不满足就返回 `None`（**宁可读不到，不可读错**）：
   - 连通域个数为 0 或超过 `max_digits=2`；
   - `stage` 必须形如「首位 ∈ `123456789`、次位 ∈ `1234567`」；
   - 读不到就由 `_extract_narrow` **回落到顶栏横带 OCR**，结果照旧。

## 三、三个开关（`config/config.py`）

| 键 | 默认 | 作用 |
|---|---|---|
| `STAGE_DIGIT_TPL` | `True` | `False` = 完全回到改造前（全走 OCR），用于对比/回退 |
| `STAGE_DIGIT_TPL_AUTO_LEARN` | `True` | 模板读不到但 OCR 读到 → 用 OCR 当标签自动补/替换字模 |
| `STAGE_DIGIT_TPL_VERIFY_EVERY` | `0` | 每 N 次抽检一次 OCR 交叉校验（0=关）。开了等于把省下的 146ms 又花回去，只在排查「模板悄悄读错」时临时开 |

## 四、字库会自动检查、扩充、替换

这是"字模不会悄悄过期"的关键，全部在 `learn_from_ocr()` 里，**任何异常都吞掉**（学习失败不影响识别）：

- **攒够才入库**：同一个数字连续 `AUTO_LEARN_MIN_AGREE=3` 次 OCR 结果一致才收；
- **不重复收**：与已有字模相似度 ≥ `AUTO_LEARN_SKIP_SIM=0.90` 视为"已经认识"，跳过；
- **会淘汰旧模板**：新字模与旧字模相似度 < `REPLACE_SIM=0.70` 时替换掉旧的（游戏换字体、UI 改版）；
- **不许膨胀**：每个数字硬上限 `MAX_PER_DIGIT=12` 张；
- **会熔断**：连续 `BYPASS_AFTER_STREAK=30` 次读不到 → 本进程不再用模板（`bypassed()` 为真），
  全部回落 OCR，等下次重启再试。

连续读不到还会按档位告警：10 次 `WARN`、25 次 `ERROR`（提示字模疑似过期）。

## 五、怎么重建字模

需要一批**带顶栏的真实对局截图**（客户端「保存帧」写出的 `tempdir/frames/` 就符合）：

```bash
# 从截图目录自动打标签重建（会用 OCR 读一遍拿标签, 较慢, 几分钟）
python -X utf8 -u -m utils.digit_tpl --build --dir tempdir/frames --limit 200

# 只看当前字模状态 / 健康度
python -X utf8 -u -m utils.digit_tpl --verify
```

`--dir` 不给时依次找 `workspace/agent_debug/`、`tempdir/frames/`。
重建会覆盖 `recognize/templates/stage_digits.npz`，重建前建议先 `git status` 确认没有别人改过。

## 六、验收基线（本机 RTX 4060 Ti / i5-12490F）

`tempdir/bench_digit_tpl.py`（同一帧 `tests/images/board_ingame.png` → 1920×1080，各测 3 次取 min）：

| 口径 | stage | round_time | 合计 |
|---|---|---|---|
| 模板 on | 2.21ms | 2.42ms | **3.84ms** |
| 模板 off（OCR 回退） | — | — | **146.63ms** |

结果一致：`{'stage': '3-6', 'round_time': 20}`。

## 七、什么时候要留意

- **兜底率上升**：`format_health()` 里「OCR 救回」次数持续变多，说明字模开始跟不上画面
  （换分辨率、换皮肤主题、UI 改版）。重建一次即可。
- **改分辨率**：四个区域坐标是 1920×1080 基准写死的，非 16:9 或非 1080p 要先缩放整帧。
- **换游戏语言/字体**：字模是字形匹配，换字体后相似度会掉，靠自学习慢慢补，急的话直接 `--build`。
